# STEP 1 — Deep Explanation

## 1. Overview of Interrupt

### Definition

An interrupt is a signal sent to the processor by an external device to request that the processor perform a particular task.

In a microprocessor-based system, interrupts are mainly used for transferring data between peripheral devices and the microprocessor.

### Why are interrupts needed?

Imagine that a computer is receiving data from a keyboard. When a key is pressed, the keyboard can send an interrupt signal to the processor to indicate that it needs attention.

Instead of continuously checking whether the keyboard has data, the processor can perform other work and respond when the interrupt occurs.

### Working of an interrupt

1. Peripheral device becomes ready

Example: A keyboard has new data.

2. Interrupt signal is sent

The signal reaches an interrupt pin of the 8085.

3. Processor executes the ISR

The processor performs the required interrupt-handling task.

4. Normal activity resumes

The processor returns to its interrupted program.

### Important term: ISR

ISR stands for Interrupt Service Routine.

An ISR is a sequence of instructions executed by the processor to handle a particular interrupt.

For example, when a peripheral requests data transfer, the ISR can perform the necessary data-handling operation.

### Interrupt-driven data transfer

According to the PPT, when a peripheral is ready for data transfer, it sends an appropriate signal to an interrupt pin of the processor. After executing the ISR, the processor resumes its current activity.

This data-transfer method is called the interrupt-driven data transfer scheme.

Exam points:

* An interrupt is a signal requesting processor attention.

* Interrupts are useful for communication between peripherals and the microprocessor.

* ISR means Interrupt Service Routine.

* The processor resumes its previous activity after servicing the interrupt.

* The method is called interrupt-driven data transfer.

## 2. Types of Interrupts

The 8085 microprocessor supports five interrupt pins:

* TRAP

* RST 7.5

* RST 6.5

* RST 5.5

* INTR

The PPT classifies interrupts into two main types: software interrupts and hardware interrupts.

Interrupts

1. Software Interrupts

Generated by program instructions.

The interrupt instruction is placed at a desired location in a program.

2. Hardware Interrupts

Initiated by external devices.

Asynchronous in nature and classified as maskable or non-maskable.

### 2.1 Software interrupts

Definition: Software interrupts are interrupts generated by program instructions.

These instructions are inserted at desired locations in a program. When the processor encounters a software interrupt instruction during program execution, it executes the corresponding Interrupt Service Routine (ISR).

Example: A program contains an interrupt instruction at a particular point. When execution reaches that instruction, the processor performs the associated interrupt-handling operation.

Key points:

* Generated through instructions in a program.

* Occur when the processor encounters the relevant instruction.

* Cause execution of an ISR.

### 2.2 Hardware interrupts

Definition: Hardware interrupts are interrupts initiated by an external device.

They are asynchronous, meaning that their occurrence is not necessarily tied to the exact point currently being executed in the program.

Example: A peripheral device sends an interrupt signal to the processor when it needs attention.

The PPT further classifies hardware interrupts into two types.

#### A. Maskable interrupt

A maskable interrupt is one that can be disabled or masked by the processor's interrupt-control mechanism.

In the 8085, the four maskable interrupt inputs are:

* RST 7.5

* RST 6.5

* RST 5.5

* INTR

The EI, DI, and SIM instructions are relevant to interrupt control, as explained later.

#### B. Non-maskable interrupt

A non-maskable interrupt cannot be disabled through the normal interrupt-masking mechanism used for maskable interrupts.

The 8085's TRAP is its non-maskable interrupt.

### Comparison: Software vs Hardware Interrupts

| Basis         | Software interrupt                             | Hardware interrupt                          |
| ------------- | ---------------------------------------------- | ------------------------------------------- |
| Origin        | Program instruction                            | External device                             |
| Nature        | Instruction-triggered                          | Asynchronous                                |
| How it occurs | Processor encounters the interrupt instruction | Device sends an interrupt signal            |
| Example       | An interrupt instruction in a program          | A peripheral requesting processor attention |

Exam points:

* The 8085 supports five interrupt pins.

* Software interrupts are generated by instructions.

* Hardware interrupts are initiated by external devices.

* Hardware interrupts are classified as maskable and non-maskable.

* TRAP is non-maskable; RST 7.5, RST 6.5, RST 5.5, and INTR are maskable.

## 3. Enabling and Disabling Interrupts

The 8085 provides two instructions to enable and disable interrupts:

* EI — Enable Interrupts

* DI — Disable Interrupts

These instructions control the four maskable interrupts listed in the PPT.

### 3.1 EI — Enable Interrupts

Definition: EI is an instruction used to enable interrupts.

It enables the interrupt system for the four maskable interrupt inputs:

* RST 7.5

* RST 6.5

* RST 5.5

* INTR

Once enabled, these interrupts can be recognized according to the processor's interrupt-handling rules and their individual mask settings.

### 3.2 DI — Disable Interrupts

Definition: DI is an instruction used to disable interrupts.

It disables the four maskable interrupts listed above through the general interrupt-enable mechanism.

### Comparison between EI and DI

| Basis             | EI                              | DI                              |
| ----------------- | ------------------------------- | ------------------------------- |
| Full form         | Enable Interrupts               | Disable Interrupts              |
| Purpose           | Enables maskable interrupts     | Disables maskable interrupts    |
| Affected inputs   | RST 7.5, RST 6.5, RST 5.5, INTR | RST 7.5, RST 6.5, RST 5.5, INTR |
| Conditional flags | Not affected                    | Not affected                    |

### What are implied instructions?

The PPT states that EI and DI are implied instructions.

An implied instruction does not explicitly specify an operand in the instruction itself; the operation is understood from the instruction.

The PPT also states that EI and DI do not affect conditional flags. This means executing these instructions does not change the processor's conditional flag status.

Exam points:

* EI enables interrupts.

* DI disables interrupts.

* EI and DI apply to four maskable interrupt inputs.

* Neither instruction affects conditional flags.

* TRAP is not controlled by EI and DI as a maskable interrupt.

## 4. Vectored and Non-Vectored Interrupts

This topic explains how the processor obtains the address at which interrupt handling begins.

### 4.1 Vectored interrupts

Definition: Vectored interrupts are interrupts that have a fixed memory location for transferring control from normal program execution.

The processor can use the predefined location associated with the interrupt to begin its interrupt-handling routine.

The PPT lists these vectored interrupts:

* TRAP

* RST 7.5

* RST 6.5

* RST 5.5

### 4.2 Non-vectored interrupts

Definition: Non-vectored interrupts do not have a fixed memory location for transferring control from normal execution.

According to the PPT, the address of the memory location is sent along with the interrupt.

The 8085's INTR is a non-vectored interrupt.

### Comparison: Vectored vs Non-Vectored Interrupts

| Basis               | Vectored                        | Non-vectored                             |
| ------------------- | ------------------------------- | ---------------------------------------- |
| Memory location     | Fixed, predefined location      | No fixed location                        |
| Address information | Associated with the interrupt   | Address is sent along with the interrupt |
| 8085 examples       | TRAP, RST 7.5, RST 6.5, RST 5.5 | INTR                                     |

Exam points:

* Remember the four vectored interrupts.

* INTR is the non-vectored interrupt.

* Vectored interrupts have fixed memory locations.

* Non-vectored interrupts receive address information along with the interrupt.

## 5. SIM and RIM Instructions

SIM and RIM are special 8085 instructions related to interrupt control and serial input/output.

### 5.1 SIM — Set Interrupt Mask

Definition: SIM stands for Set Interrupt Mask.

According to the PPT, this instruction reads the contents of the accumulator and enables or disables interrupts according to the accumulator's contents.

In other words, the accumulator supplies control information used by SIM to configure interrupt masking.

Basic working:

```
Accumulator contains control information
                 |
                 v
            SIM executes
                 |
                 v
 Interrupt mask settings are updated
 according to the control information
```

Example: A program prepares the appropriate control information in the accumulator and executes SIM to change the interrupt-mask settings.

Important point: SIM uses the accumulator's contents; it is not an instruction that reads the current interrupt status into the accumulator.

### 5.2 RIM — Read Interrupt Mask

Definition: RIM stands for Read Interrupt Mask.

According to the PPT, this instruction loads the accumulator with information about:

* The current status of the interrupt mask.

* The interrupt-enable status.

* Pending interrupts.

* Serial input data.

Basic working:

```
Current interrupt and serial-input status
                 |
                 v
            RIM executes
                 |
                 v
 Accumulator receives status information
```

Example: A program executes RIM to read the current interrupt-related status information into the accumulator.

### Comparison: SIM vs RIM

| Basis                           | SIM                                                              | RIM                                                                                  |
| ------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Full form                       | Set Interrupt Mask                                               | Read Interrupt Mask                                                                  |
| Main purpose                    | Set or control interrupt masking                                 | Read interrupt-related status                                                        |
| Information flow                | Accumulator → interrupt-control mechanism                        | Interrupt/status information → accumulator                                           |
| Other function mentioned in PPT | Enables or disables interrupts according to accumulator contents | Reads pending interrupts, interrupt-enable status, mask status and serial input data |

Easy memory trick:

* SIM = Set — use accumulator information to configure interrupt masking.

* RIM = Read — read interrupt and serial-input status into the accumulator.

Exam points:

* SIM means Set Interrupt Mask.

* RIM means Read Interrupt Mask.

* SIM reads the accumulator's contents to control interrupt masking.

* RIM loads the accumulator with interrupt-mask status, interrupt-enable status, pending-interrupt information and serial-input data.

## Q18. Write short notes on ISR, interrupt-driven data transfer, and interrupt classification. (5 Marks)

Answer:

An ISR is a routine executed by the processor to service a particular interrupt. After servicing the interrupt, the processor resumes its previous activity.

### 2. Interrupt-Driven Data Transfer

When a peripheral device becomes ready, it sends an interrupt signal to the processor. The processor executes the relevant ISR and then resumes its previous activity. This process is called interrupt-driven data transfer.

### 3. Interrupt Classification

The PPT describes two main categories:

* Software interrupts: Generated through program instructions.

* Hardware interrupts: Initiated by external devices and further classified as maskable and non-maskable.

The five hardware interrupt pins are TRAP, RST 7.5, RST 6.5, RST 5.5 and INTR.
